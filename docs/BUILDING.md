# Building from source

Prebuilt binaries do not need any of this. You only need a Rust toolchain
to build lasrs-cpp itself from source.

## Requirements

| Tool | Version | Notes |
|---|---|---|
| Rust (rustup) | pinned by `rust-toolchain.toml` | installs `rustc` and `cargo` |
| CMake | 3.22+ | |
| C++ compiler | C++20 | MSVC 2022, GCC 11+, Clang 16+, Apple Clang 15+ |
| Ninja | any | optional, faster builds |

### Windows

```
winget install Rustlang.Rustup
winget install Kitware.CMake
winget install Ninja-build.Ninja
```

Use the default `x86_64-pc-windows-msvc` Rust toolchain. Open a new
terminal afterwards so PATH is updated. The Ninja presets need the MSVC
environment, so build from a "Developer PowerShell for VS".

### Linux / macOS

```
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

Install CMake and a C++ compiler with your package manager.

## Build

```
cmake --preset release
cmake --build --preset release
ctest --preset release
```

The first build downloads Corrosion, Catch2 and the Rust crates and
compiles them; later builds are incremental.

## Test data

Configuring the tests copies the sample files that ship with the las crate
into `test_data/` (gitignored). Larger local files can be dropped there
too: tests for `reel_0005_20250821-165617_pointcloud.laz` run when it is
present and are skipped otherwise.

## Using from another CMake project

```cmake
include(FetchContent)
FetchContent_Declare(lasrs
  GIT_REPOSITORY https://github.com/bloom256/lasrs-cpp.git
  GIT_TAG main)
FetchContent_MakeAvailable(lasrs)

target_link_libraries(my_app PRIVATE lasrs::lasrs)
```

## The library bundle

`cmake --install` produces a self-contained bundle:

```
include/lasrs/            C++ headers (lasrs.hpp) and the C header (lasrs.h)
lib/lasrs_ffi.lib         static library (liblasrs_ffi.a on Linux/macOS)
lib/cmake/lasrs/          CMake package config
share/lasrs/              licenses and THIRD-PARTY-NOTICES.txt
```

```
cmake --preset release -DLASRS_BUILD_TESTS=OFF -DLASRS_BUILD_EXAMPLES=OFF
cmake --build --preset release
cmake --install build/release --prefix <dir>
```

CI builds this bundle for Windows x64, Linux x64 and macOS arm64 on every
run and keeps it as a downloadable workflow artifact for 30 days.

### Using the bundle with CMake

```cmake
find_package(lasrs REQUIRED)   # with -DCMAKE_PREFIX_PATH=<dir>
target_link_libraries(my_app PRIVATE lasrs::lasrs)
```

### Using the bundle without CMake

Compile as C++20 with `<dir>/include` on the include path and link the
static library plus the system libraries the Rust code needs:

- Windows (MSVC): `lasrs_ffi.lib kernel32.lib ntdll.lib userenv.lib
  ws2_32.lib dbghelp.lib`. The library uses the dynamic release CRT (`/MD`).
- Linux: `-llasrs_ffi -lgcc_s -lutil -lrt -lpthread -lm -ldl`
- macOS: see `lib/cmake/lasrs/lasrs-config.cmake`, which lists the exact
  system libraries for the platform the bundle was built on.

## Regenerating the C header

The C header `include/lasrs/lasrs.h` is generated by cbindgen and
committed. After changing exported Rust functions:

```
cargo install cbindgen
cbindgen --config rust/cbindgen.toml --crate lasrs_ffi --output include/lasrs/lasrs.h rust
```

CI fails if the committed header is out of date.
