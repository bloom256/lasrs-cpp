# Architecture

## Overview

lasrs-cpp is a wrapper, not a port. All format work (LAS parsing, the LAZ
arithmetic codec, COPC hierarchy) is done by existing Rust crates. This
repository adds three thin layers on top:

```
+--------------------------------------------------+
|  C++ API   include/lasrs/lasrs.hpp               |  header-only, C++17
|            RAII handles, std::span, exceptions   |
+--------------------------------------------------+
|  C ABI     include/lasrs/lasrs.h                 |  generated by cbindgen
|            opaque handles, status codes          |
+--------------------------------------------------+
|  Rust shim rust/src/*.rs  (crate: lasrs_ffi)     |  staticlib
|            extern "C" fns, catch_unwind          |
+--------------------------------------------------+
|  Upstream  las, laz (parallel, rayon), copc-rs   |  from crates.io
+--------------------------------------------------+
```

Users link one static library (`lasrs_ffi`) and include the headers. The
final application has no Rust runtime dependency and no extra DLLs.


## Performance rules

The language boundary costs a few nanoseconds per call. It only matters if
it is crossed per point. Therefore:

1. **Batch everything.** Every read/write call moves many points (a chunk
   or a caller-sized buffer). There is no per-point FFI function.
2. **Zero copy.** The caller owns the buffer (`std::span<std::byte>` or
   typed columns); Rust decodes directly into it. No intermediate `Vec`
   that is later copied.
3. **Parallelism lives in Rust.** One call may decode many LAZ chunks
   concurrently on the rayon pool. C++ does not drive threads per chunk.
4. **Layout is chosen up front.** Either raw LAS point records (AoS, exact
   on-disk layout after decompression) or SoA columns (x[], y[], z[],
   intensity[], ...). Rust fills the requested layout in one pass.

## FFI rules

1. **Opaque handles.** `lasrs_reader*`, `lasrs_writer*`, `lasrs_copc*`.
   Created and freed only by Rust (`lasrs_*_open` / `lasrs_*_free`).
2. **No cross-allocator frees.** Memory allocated by Rust is freed by
   Rust; memory owned by C++ is never freed by Rust.
3. **No panics across the boundary.** Every exported function runs inside
   `std::panic::catch_unwind` and returns a `lasrs_status` code.
4. **Error details.** On failure a thread-local error message is stored;
   `lasrs_last_error()` returns it. The C++ wrapper converts non-OK
   status into `lasrs::Error` (derived from `std::runtime_error`).
5. **Plain C types only.** Fixed-width integers, `double`, pointers,
   `size_t` lengths. Paths are passed as UTF-8 `const char*` (Windows
   callers convert from wide strings in the C++ wrapper).
6. **ABI version.** `lasrs_abi_version()` lets the C++ header detect a
   mismatched prebuilt library at startup.

## Build

- CMake drives everything. Corrosion (fetched with FetchContent) invokes
  cargo, builds the shim as a static library and exposes it as a CMake
  target, including the platform system libraries a Rust staticlib needs.
- `rust-toolchain.toml` pins the Rust version; `Cargo.lock` pins crates.
- `CMakePresets.json` provides standard configurations.
- The C header is regenerated by cbindgen and committed, so prebuilt
  users never need cbindgen.

## Distribution

1. **From source**: CMake + Corrosion, requires Rust.
2. **Prebuilt**: CI builds static libs per platform and attaches them to
   GitHub releases, together with headers, a CMake package config and
   `THIRD-PARTY-NOTICES`. No Rust needed.
3. **vcpkg**: overlay port first (`ports/lasrs-cpp`), official registry
   later.

Windows prebuilts come in two variants: `/MD` (dynamic CRT, default) and
`/MT` (static CRT).
