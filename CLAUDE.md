# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

lasrs-cpp is a C++ wrapper (not a port) around the Rust crate las-rs
(with laz-rs for parallel LAZ). The C++ API mirrors las-rs names and
exposes only what las-rs offers. See docs/ARCHITECTURE.md for the design
and the Rust-to-C++ translation rules, docs/ROADMAP.md for milestones.

## Layout

- `rust/` - shim crate `lasrs_ffi` (staticlib, extern "C")
- `include/lasrs/lasrs.h` - C API, generated by cbindgen, committed
- `include/lasrs/*.hpp` - header-only C++20 wrapper, `namespace las`
- `tests/`, `examples/` - C++ tests and examples; `tests/package/` builds C
  and C++ programs against an installed bundle
- `benchmarks/` - comparison with LASzip, laz-perf, PDAL, laspy; its own
  pixi environment (`benchmarks/pixi.toml`), not part of the library build
- `.github/workflows/` - `ci.yml`, `bundle.yml` (reusable, all platform
  bundles), `release.yml` (on `vX.Y.Z` tags), `codeql.yml`
- `test_data/` - gitignored; sample files copied by CMake, the downloaded
  benchmark tile, the maintainer's own large files, outputs

## Commands

On Windows run CMake from a VS developer shell (MSVC environment).

```
cmake --preset release
cmake --build --preset release
ctest --preset release
cargo fmt --manifest-path rust/Cargo.toml
cargo clippy --manifest-path rust/Cargo.toml --all-targets -- -D warnings
git ls-files '*.hpp' '*.cpp' | xargs clang-format -i
cbindgen --config rust/cbindgen.toml --crate lasrs_ffi --output include/lasrs/lasrs.h rust
(cd rust && cargo deny check)

# install a bundle and run the test suite against it
cmake --install build/release --prefix build/install
cmake -S tests -B build/tests-standalone -DCMAKE_PREFIX_PATH=build/install -DLASRS_TEST_DATA_DIR=test_data

# benchmarks (downloads a 952 MB public tile on first run)
cd benchmarks && pixi run bench
```

Linux can be checked locally in WSL (Ubuntu 24.04 and 20.04 are
installed). CI runs clang-format 21.1.8, cbindgen 0.29.4 and cargo-deny
0.20.2; use the same versions locally.

## Coding principles

- Code must be self-explanatory: clear names, small functions, simple
  control flow. Do not write comments that restate what the code does.
  If a comment seems necessary, first ask whether the code is
  overcomplicated and simplify it instead. Comment only genuinely tricky
  code (non-obvious invariants, format quirks, spec references, why not
  what).
- Do not reinvent the wheel. Never hand-roll math, geometry, CRS
  transforms, parsing, containers, threading primitives, etc. Use
  well-known libraries (std, Boost, Eigen, PROJ, fmt, Catch2 in C++;
  established crates in Rust). Stand on the shoulders of giants.
- Dependency budget: the shipped library (`lasrs_ffi` + public headers)
  keeps dependencies minimal because users inherit them. Tests, examples,
  benchmarks and tools may use any well-known library.
- Follow each language's established best practices.
- C++: follow the C++ Core Guidelines. RAII everywhere, no owning raw
  pointers, no naked new/delete, const by default, std::span / string_view
  for non-owning views, no macros where a language feature works.
- Rust: idiomatic Rust, `cargo clippy` clean, `unsafe` only at the FFI
  boundary and kept as small as possible.
- Keep it simple (KISS, YAGNI): implement what the roadmap needs now, no
  speculative abstractions or configuration knobs.
- Fail loudly: no silently swallowed errors; propagate with context.
- Match surrounding code style; formatting is done by `cargo fmt` and
  `clang-format` (Microsoft style), not by hand.

## Rules

- Commit every feature separately in small commits. Push only when the
  maintainer asks; `main` is protected by a ruleset (admins may push
  directly, everyone else goes through PRs with green CI).
- Releases only on the maintainer's explicit request, following
  docs/RELEASING.md (plain annotated tag, no GPG).
- Large files (test data, build output) live in gitignored folders inside
  the repo, never in temp directories.
- 7-bit ASCII only in all code and docs.
- SPDX header `MIT OR Apache-2.0` on new source files.
- FFI: batch-oriented, per-point calls only where las-rs itself has them;
  opaque handles freed by Rust; every fallible export wrapped in
  catch_unwind and returns a status code; C++ stream callbacks never throw.
- Regenerate and commit `lasrs.h` after changing exports.
- New Rust dependencies must have permissive licenses (cargo deny).
- All building, testing and releasing is automated in GitHub Actions.
  Keep CI green; new features come with tests that run in CI.
- New las-rs features get the same names in C++; follow the translation
  rules in docs/ARCHITECTURE.md.
- Benchmark numbers in the README come from the reproducible public tile
  (`pixi run bench`), tables sorted by time, with peak memory.
